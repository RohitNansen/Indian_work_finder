## Document limits

A PDF contains positioned text rather than the original Word paragraph structure. The exported Word copy therefore uses editable text boxes; font rendering can vary between Word installations. Exact editable fidelity for every future file cannot be guaranteed. Uploading the original DOCX retains its native structure. Edits that do not fit a PDF are rejected rather than shrinking fonts or moving other sections. A user can deselect or shorten a suggested edit before export.

## Company application limits

A company may require its own recruitment account. Verification cannot bypass that requirement, bot protection, or a closed vacancy. Unverifiable jobs do not enter new shortlists. Earlier search history remains visible, but intermediary application redirects are blocked and a Find company application button is provided. Request limits include discovery calls. Search and verification can take several minutes.

## Operations

The VM has a dedicated 1 GB swap file to support document rendering alongside existing apps. LibreOffice Writer and Caladea fonts support Word-to-PDF output. Existing Nginx routes and ports are preserved. No application email is sent by this upgrade. `data/`, resume files, credentials and candidate login details remain outside Git.

## Owner testing

1. Sign in with `admin` and the existing owner password. In My profile, set the candidate's six-character password.
2. Sign out; sign in using the exact profile name and the new password. Confirm Activity is absent.
3. Run a small search, inspect the company/status summary, open a role and check its company link.
4. Save answers, confirm green status, edit an experience statement and replace the resume if desired.
5. Prepare a resume copy, approve only truthful edits, and inspect the downloaded PDF and Word copy.
6. Resume daily alerts only when ready. They remain paused during this testing.
